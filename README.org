#+TITLE: HiddenGit
#+SUBTITLE: Release 0.1.1

HiddenGit is a small, self-hosted Soft Serve Git forge published as a Tor v3
onion service. Docker Compose manages the local services; the default product
profile exposes authenticated SSH only. HTTP, native =git://=, and LFS are
disabled; statistics remain container-loopback only.

This remains an experimental deployment. Review =issues.yml= before treating it
as a high-assurance service.

The full operator/developer documentation is published from exact release tags
at [[https://hiddengit.fkr.dev][hiddengit.fkr.dev]]. The system boundaries and state model are documented in
=ARCHITECTURE.md=. Release sequencing lives in =ROADMAP.md=, and =RELEASING.md=
defines the SemVer, changelog, validation, commit, tag, hosted-release, and
release-documentation contract.

* Security model

- Tor keeps the server's public network location out of the clone URL.
- Soft Serve authenticates operators and collaborators with SSH public keys.
- The only default host-published Soft Serve endpoint is SSH; it binds to
  =127.0.0.1= by default and maps =LOCAL_SSH_PORT= to fixed internal =23231=.
- Runtime state under =data/= contains private SSH keys, repositories, the
  SQLite database, and the Tor onion identity. It must never be committed.
- A fresh deployment refuses to boot without at least one initial administrator
  public key.

The onion address is not itself an access-control mechanism. Configure private
repositories and collaborators in Soft Serve. Tor v3 client authorization is
tracked separately in =issues.yml=.

* Requirements

- Docker Engine with Docker Compose v2
- Bash, awk, grep, and standard Unix utilities
- Optional: [[https://arti.torproject.org/related/oniux/][oniux]] for a host-side connectivity check
- Optional development checks: ShellCheck and yamllint

* Quick start

1. Create local configuration and private state directories:

   #+begin_src shell
   ./run.sh init
   #+end_src

2. Edit =.env= and set a complete SSH public key:

   #+begin_src conf
   SOFT_SERVE_INITIAL_ADMIN_KEYS="ssh-ed25519 AAAA... operator@example"
   #+end_src

3. Validate the versioned configuration, audit posture, and start:

   #+begin_src shell
   ./run.sh config check
   ./run.sh doctor
   ./run.sh up
   #+end_src

4. Print the generated onion hostname and public SSH port:

   #+begin_src shell
   ./run.sh status
   #+end_src

5. Stop the stack without deleting persistent state:

   #+begin_src shell
   ./run.sh down
   #+end_src

* Configuration

Copying =env.example= manually is supported, but =./run.sh init= also applies
safe file permissions.

Set =HIDDEN_GIT_ENV_FILE=/path/to/file= to operate against a non-default
environment file. Runtime data remains under this checkout's =data/= directory.

Configuration is versioned independently from the software release by
=HIDDEN_GIT_CONFIG_VERSION=. Current files must pass =./run.sh config check=.
Older environment files are migration inputs rather than silently compatible
Compose inputs: preview them with =./run.sh config migrate= and apply only after
review with =./run.sh config migrate --apply=. Unknown, duplicate, malformed,
and ambiguous values fail before Compose can interpret them differently.

** Images and versions

- =HIDDEN_GIT_VERSION= :: Project release version; must match =VERSION=.
- =ALPINE_IMAGE= :: Minimal runtime base for every release image, pinned by
  multi-architecture OCI digest.
- =GO_IMAGE= :: Go builder image, pinned by multi-architecture OCI digest.
- =SOFT_SERVE_VERSION= :: Pinned upstream Soft Serve release; current release
  source targets =v0.12.2=.
- =SOFT_SERVE_*_VERSION= :: Explicit reviewed dependency versions aligned with
  the selected upstream Soft Serve graph. They are release-managed, not normal
  deployment knobs.
- =TRIVY_IMAGE= :: Digest-pinned scanner used only for release evidence.
- =BUILDKIT_IMAGE= :: Digest-pinned BuildKit worker used for provenance builds.

** Service identity and access

- =SOFT_SERVE_NAME= :: Name shown in the Soft Serve UI.
- =SOFT_SERVE_INITIAL_ADMIN_KEYS= :: Required administrator SSH public keys on
  first boot. Existing databases do not require it again.
- =SOFT_SERVE_SSH_USER= :: Username used only by readiness probes.

** Network intent

- =LOCAL_SSH_PORT= :: Loopback-facing host SSH port. Docker maps it to managed
  internal Soft Serve SSH =23231=.
- =ONION_PUBLIC_PORT= :: Virtual port clients use on the onion address. Tor maps
  it to the same managed internal SSH endpoint =soft-serve:23231=.
- =HOST_BIND_ADDRESS= :: Host address for the local SSH publication. Keep the
  default =127.0.0.1= unless wider LAN exposure is intentional and reviewed.
- =SOFT_SERVE_SSH_PUBLIC_URL= :: Optional =ssh://= clone-hint override. Empty
  derives =ssh://localhost:<LOCAL_SSH_PORT>=. Public URL and listener are not
  forced equal because proxies/Tor may intentionally differ.

Internal ports are no longer public configuration. The data path, Tor target,
CI mode, Soft Serve SSH/HTTP/stats/Git ports, protocol enablement, and LFS policy
are managed product invariants. The default generated config enables SSH on
=:23231=, disables HTTP and native =git://=, keeps stats on
=127.0.0.1:23233=, and disables LFS/SSH-LFS.

** Runtime and checks

- =SOFT_SERVE_SSH_USER= :: Username used only by readiness probes.
- =CHECK_TIMEOUT_SECONDS= :: Upper bound for each live onion SSH verification.

The machine-readable contract is =config/schema.json=. Legacy
=SOFT_SERVE_*_PORT=, =ONION_TARGET_PORT=, =SOFT_SERVE_DATA_PATH=, and =CI=
values are handled only by =config migrate=; they are not current settings.

** Backups

- =BACKUP_RECIPIENT= :: Public age recipient used to encrypt backups. The
  matching identity must remain offline and outside this repository.
- =BACKUP_IDENTITY_FILE= :: Optional local default identity path for restore.

Run =./run.sh doctor= for actionable PASS/WARN/FAIL output. It reports valid but
risky choices such as non-loopback publication, permissive secret directories,
mutable dependency references, stale backups, or a non-rootless Docker daemon.
=./run.sh doctor --strict= turns warnings into a non-zero exit status.

Existing deployments can adopt reviewed version and digest references without
changing deployment intent:

#+begin_src sh
./run.sh sync-pins
#+end_src

=sync-pins= is deliberately separate from schema migration. It creates a private
rollback copy and refreshes release-managed inputs, but does not pretend an old
schema became current. Use =config migrate= for that transformation.

* Encrypted backup and restore

Generate a backup identity once:

#+begin_src sh
./run.sh backup-keygen
#+end_src

Store =backups/backup-identity.agekey= offline, then copy the displayed public
recipient into =BACKUP_RECIPIENT=. For a consistent snapshot, stop services and
create the backup:

#+begin_src sh
./run.sh down
./run.sh backup
#+end_src

Restore refuses to overwrite existing data. Preserve the onion address with
=preserve=, or deliberately create a new one with =rotate=:

#+begin_src sh
./run.sh restore backups/hidden-git-backup-YYYYmmddTHHMMSSZ.tar.age \
  /offline/path/backup-identity.agekey preserve
#+end_src

Age authenticates the ciphertext; the archive also contains per-file SHA-256
checksums and has a checksum sidecar. See =SECURITY.md= for operational limits.

* Connecting through Tor

Assume =./run.sh status= reports =example.onion= and port =8002=.

** With oniux

#+begin_src sshconfig
Host hiddengit
  HostName example.onion
  User admin
  Port 8002
  ProxyCommand oniux nc %h %p
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
  StrictHostKeyChecking accept-new
#+end_src

Then open the Soft Serve TUI:

#+begin_src shell
ssh hiddengit
#+end_src

Clone a repository using the same SSH host alias:

#+begin_src shell
git clone ssh://hiddengit/OWNER/REPOSITORY.git
#+end_src

** With torsocks

#+begin_src shell
torsocks ssh -p 8002 admin@example.onion
#+end_src

* Persistent data and permissions

| Host path | Contents | Sensitivity |
|-----------+----------+-------------|
| =data/soft-serve/= | Repositories, SQLite DB, Soft Serve SSH keys | Secret/private |
| =data/tor/= | Tor state and persistent onion identity | Secret/private |
| =backups/= | Encrypted archives; identity files must be moved offline | Private |

Back up both directories together. Do not copy them into release archives or
bug reports. Soft Serve runs as =10001:10001= and Tor as =10002:10002= with a
read-only root filesystem, no Linux capabilities, and =no-new-privileges=.

For an existing pre-migration deployment, first create and verify an encrypted
backup, stop the stack, then explicitly migrate ownership:

#+begin_src sh
./run.sh down
./run.sh backup
./run.sh migrate-users --confirm-existing
./run.sh doctor
#+end_src

Fresh empty bind mounts are migrated automatically by =./run.sh up=. Existing
state is never chowned implicitly.

If =doctor= reports legacy runtime directories, run =./run.sh legacy-state=.
The command reports only file counts, byte totals, UTC modification recency,
and whether the database, SSH host identity, and onion identity are the same or different. A
=different= result represents a separate deployment: back up both before
selecting, exporting, merging, archiving, or deleting anything.

=./run.sh state-inventory= adds secret-safe database metadata. When the legacy
database contains no repositories and the current layout is authoritative,
=./run.sh reconcile-state --confirm-current-authoritative= creates and verifies
two encrypted backups, writes a reconciliation report, archives the retired
layout below =retired-state/=, and migrates current state to the service UIDs.
Move the generated age identity to durable offline storage.

Tor health is reported only after its authenticated local control port confirms
100% network bootstrap and the onion hostname exists. Onion SSH probes remain
bounded but use a longer per-attempt allowance in E2E because circuit and SSH
handshakes can legitimately span several seconds.

* Development and release checks

Run deterministic static checks:

#+begin_src shell
./tests/test.sh
#+end_src

Build all images:

#+begin_src shell
./run.sh build
#+end_src

The live end-to-end check requires a running stack and Tor bootstrap:

#+begin_src shell
./run.sh test
#+end_src

Run a completely isolated fresh-deployment test with generated credentials,
random local ports, and disposable named volumes:

#+begin_src shell
./tests/e2e.sh
#+end_src

This validates database initialization, the generated Soft Serve configuration,
authenticated local SSH, and authenticated SSH through the onion service without
touching =./data= or =.env=. Set =KEEP_E2E_ARTIFACTS=1= to retain failure logs.

GitHub Actions runs the static checks and image build for pushes and pull
requests. The onion end-to-end job uses disposable credentials and volumes and
uploads its retained workspace when it fails. Dependency update proposals are
configured in =.github/dependabot.yml=.

Rootless compatibility is validated against a digest-pinned official rootless
Docker daemon:

#+begin_src shell
./tests/rootless-docker.sh
#+end_src

The harness covers Compose builds, bind-mounted ownership, stable service UIDs,
read-only roots, and dropped capabilities.

Tagged and manually requested CI runs also execute =./run.sh evidence=. A
temporary BuildKit container builder emits SLSA v1 provenance into OCI archives;
the digest-pinned Trivy image then produces CycloneDX SBOMs and JSON/text
vulnerability reports. The bulky OCI archives are discarded after extraction
unless =KEEP_EVIDENCE_IMAGES=1= is set.

Release evidence uses strict policy: any HIGH or CRITICAL finding fails the
release. Every candidate release must regenerate this evidence for its exact
image and dependency set before tagging.

Release metadata lives in =VERSION= and =CHANGELOG.md=. =RELEASING.md= defines
the complete local release gate. Deferred larger work is kept in =issues.yml=
and sequenced in =ROADMAP.md=.
